# Project Style Guide

## UI Style
- **Visual direction**: dark premium SaaS (Linear/Vercel-style) — chosen explicitly by the user from two directions on 2026-08-17 (see `DECISIONS.md`). Not a light theme; no theme toggle exists yet.
- **Styling method**: hand-written CSS per feature area (`styles/index.css`, `layout.css`, `components.css`, `pipeline.css`, `dashboard.css`), no component library (Tailwind/MUI). Files are organized by actual usage (shared UI kit vs. genuinely distinct areas like the kanban board and dashboard), not a 1:1 mapping to every domain — leads/customers reuse the same generic classes rather than getting their own CSS files.
- **Color system**: layered dark surfaces, never pure black — `--color-bg` (#0a0a0f, page) → `--color-surface` (#131319, cards/sidebar) → `--color-surface-2` (#191921, inputs/elevated) → `--color-surface-hover`. Text: `--color-text` (off-white, not pure white) / `--color-text-secondary` / `--color-muted`. Accent: `--color-primary` (#7c6ef2, violet/indigo) with a `--shadow-glow` for emphasis. Semantic colors (`--color-danger/success/warning/info`) each have a `-soft` background variant for badges/toasts. All defined once in `styles/index.css`.
- **Typography**: Inter (Google Fonts, loaded in `index.html`), weights 400–800. Headings use `letter-spacing: -0.02em` for a tighter, more "designed" feel.
- **Icons**: `lucide-react` throughout — sidebar nav, buttons ("Add X" gets `Plus`, back-links get `ArrowLeft`, edit gets `Pencil`), status badges, loading spinner (`Loader2`, animated). Icon-led UI is a deliberate part of the premium feel, not decoration for its own sake.
- **Spacing**: 4px base scale via CSS variables (`--space-1: 4px` … `--space-7: 48px`).
- **Border radius**: `--radius-sm: 8px`, `--radius-md: 12px`, `--radius-lg: 16px` (auth card, modals) — softer/larger than a typical light-theme default, matches the premium direction.
- **Shadows**: `--shadow-card` (subtle, default cards), `--shadow-raised` (modals, auth card — deeper, dark backgrounds need more contrast to read as "elevated"), `--shadow-glow` (accent-colored, for the brand mark and primary buttons).
- **Buttons**: primary (violet gradient + glow), secondary (surface + border), danger (soft red background, not solid) — one `Button` component with a `variant` prop; icon + label as children, `gap` handled by `.btn`.
- **Forms**: labeled inputs stacked vertically, inline validation error text below the field. **No dedicated `Input`/`Select` wrapper components** — plain semantic HTML styled via CSS classes (`.entity-form input`, etc.) plus a **global baseline** (`index.css`: bare `input`/`select`/`textarea` get sane dark styling, including `color-scheme: dark` for native browser chrome) so a control never renders unstyled just because it's outside a known wrapper class. See `DECISIONS.md` for the bug this baseline was added to prevent. The one exception is `components/common/Combobox.jsx` — a searchable single-select (ARIA combobox/listbox pattern, keyboard nav, client-side filtering) purpose-built for pickers backed by longer or growing lists (`OpportunityForm`'s customer picker, `LinkPicker`'s record picker); ordinary fixed-enum fields (source, status, role, stage) stay plain `<select>`s.
- **Cards**: the `.detail-card` / `.stat-card` / `.dashboard-card` pattern — dark surface, hairline border, generous padding, small accent touches (e.g. `.stat-card`'s top gradient line).
- **Tables**: `.data-table` — dark header row, hover-highlighted rows, border-bottom row separators.
- **Modals**: centered overlay with backdrop blur, used for create/edit forms rather than separate pages, so list context isn't lost. Subtle rise-in animation. Focus-trapped (Tab/Shift+Tab cycle inside the dialog), closes on Escape or backdrop click, `role="dialog"`/`aria-modal`/`aria-labelledby`, body-scroll locked while open, focus restored to the trigger on close.
- **Notifications**: `ToastContext`/`useToast()` — a global, auto-dismissing (5s) toast stack, bottom-right, for actions with no adjacent form (completing a follow-up, changing a status). Each of the four tones (success/danger/warning/info) gets a matching icon, an explicit close affordance alongside click-to-dismiss, and a fade/slide exit animation; the stack carries `role="status" aria-live="polite"` for screen readers. Form-level errors stay inline (`.form-error`), not toasted.
- **Loading states**: shape-matched skeleton screens (`components/common/Skeleton.jsx` — `TableSkeleton`, `StatGridSkeleton`, `DashboardCardsSkeleton`, `KanbanSkeleton`, `RecordListSkeleton`, `DetailSkeleton`) for list/dashboard/kanban/detail pages, so the page shell (header, filters) renders immediately and only the data-shaped region shows a loading placeholder. The `Loader` component (animated `Loader2` spinner + label) is reserved for full-page states with no shape yet to skeleton — auth-boot rehydration (`ProtectedRoute`) and the lazy-route `Suspense` fallback.
- **Empty states**: every list view has a distinct "nothing here yet" message (dashed border card) with a call-to-action, not just a blank table.
- **Error states**: failed API calls surface inline form errors or a toast with a human-readable message, never a silent failure.
- **Responsive behavior**: single breakpoint at `768px` (matches spec), collapsing multi-column layouts (kanban, dashboard grid) to a stacked/horizontal-scroll layout below it. The sidebar becomes a hamburger-triggered off-canvas drawer (backdrop, closes on Escape/backdrop click/route change) rather than a persistent column below the breakpoint. Reviewed in code; not yet device-tested (see `TECHNICAL_DEBT.md`).
- **Accessibility**: semantic HTML elements (`<button>`, `<label>`, `<table>`), visible focus rings (`:focus-visible`, accent-colored), `color-scheme: dark` for native control contrast, focus-trapped/ARIA-labeled modals, an `aria-live` toast region, global `prefers-reduced-motion` support — baseline, not a full audit, for this MVP.
- **Animations**: minimal and functional — short (150–200ms) transitions on hover/focus/modal-open, a subtle rise-in on modals/toasts, a shimmer sweep on skeleton loading states. Nothing gratuitous. All respect `prefers-reduced-motion: reduce` (global override in `index.css`).

## UX Style
- **Navigation**: persistent sidebar (desktop) with the main sections (Dashboard, Leads, Customers, Pipeline, Follow-ups, Tasks, Users[admin]); below 768px it becomes a hamburger-triggered off-canvas drawer (full labels, backdrop, closes on Escape/backdrop click/route change) rather than a persistent column.
- **Feedback patterns**: optimistic UI updates for fast actions (kanban drag), with rollback + toast on failure; a shape-matched skeleton (not a blocking spinner) for slower actions (initial page load) where avoidable.
- **Error handling UX**: form-level errors inline; system/network errors as a dismissible toast.
- **Confirmation behavior**: destructive actions (delete lead/customer/opportunity/task, deactivate user) require a `ConfirmDialog` before proceeding; non-destructive actions (stage change, status change) do not.
- **Mobile behavior**: all core flows (view/create/edit records, drag-drop stage change) must remain usable on a 375px-wide viewport, even if drag-drop degrades to a tap-to-move fallback later if needed.

## Code Style
- **Language**: plain JavaScript, ES modules (`import`/`export`), `.js` on the server, `.jsx` for React components.
- **File naming**: `kebab-case` for non-component files (`auth.service.js`), `PascalCase.jsx` for components.
- **Component naming**: `PascalCase`, named after what they render (`LeadTable`, not `LeadTableComponent`).
- **Folder conventions**: backend organized by domain module (`modules/leads/`), each with `.routes.js` / `.controller.js` / `.service.js` / `.validation.js`. Frontend organized by type first (`pages/`, `components/<domain>/`, `services/`), matching common React project conventions.
- **Function conventions**: `camelCase`, verbs for actions (`createLead`, `convertLead`), controllers stay thin (parse request → call service → shape response), business logic lives in `*.service.js`.
- **State management**: React Context for auth only; local `useState`/`useEffect` + the service layer elsewhere. No global state library introduced for MVP.
- **API patterns**: REST, resource-plural paths (`/api/leads`), standard verbs, one non-CRUD action-style endpoint where a state transition doesn't fit CRUD cleanly (`POST /leads/:id/convert`, `PATCH /opportunities/:id/stage`).
- **Error handling**: throw `ApiError(statusCode, message)` from services/controllers, caught by one global Express error-handling middleware — no scattered try/catch response-shaping.
- **Validation**: `zod` schemas per module, applied via a shared `validate` middleware — reject bad input before it reaches a controller.
- **Comments**: none by default; only where a non-obvious constraint or tradeoff needs explaining (e.g. the convert-lead idempotency note).
- **Logging**: `morgan` for HTTP request logs in dev; no structured/production logging pipeline yet (MVP scope).
- **Testing conventions**: none yet — see `TESTING.md`. When introduced, expected to be co-located `*.test.js` files run via a to-be-chosen runner (deferred decision).

> When implementing new functionality, follow this guide instead of inventing a new pattern. If a pattern is already established in the code, preserve it unless there's a strong reason to change it — record that reason in `DECISIONS.md`.
